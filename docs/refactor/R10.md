# R10. ML-авторазметка стен для органических карт. P3, L (отложено владельцем).

Назад: [REFACTOR.md](../../REFACTOR.md).

Классика (яркость/цвет/контуры/скелет) рисованные пещеры не разделяет: у «The Grotto» порода и вода одной яркости, k-means делит освещение, а не «проходимое/стена» — проверено, стенд в `lab/` (оверлеи —
`artifacts/walls-lab`).
**Что нужно:** датасет 20–40 карт стиля с разметкой «проходимое» (разметка через SAM офлайн, ~30–60 мин/карта) + процедурные карты для базы; tiny U-Net (1–3 МБ, ONNX Runtime Web: WebGPU ~0.1–0.5 с, WASM 0.5–3 с); маска →
рёбра клеток (как A++ в `lib/wallDetect.ts`) или контуры.
**Проверочный шаг:** 3–5 размеченных карт → прототип → IoU/оверлей.
**Референс detectwalls.com (разобрано 20.10.2026):** это не браузерный алгоритм — тонкий фронт режет карту на куски, шлёт на `/api/detect`, сервер с GPU (`/api/health`: `model: "v3"`) возвращает UVTT `line_of_sight`;
браузер только собирает файл и рисует превью. По ответам API: полилинии с произвольными углами (не только 0/90), средний сегмент ~0.85 клетки, координаты квантованы до 1/32 клетки; в `meta` — оценка сетки
(`pitch_source`/`pitch_confidence`), downscale, `n_polylines`/`n_segments`, `t_s`; дверей/порталов нет (`portals: 0`). На синтетической карте — 0 стен и неверная сетка, т.е. модель заточена под реальные баттлмапы. Вывод:
их пайплайн = сегментация/маска → векторизация контуров, что совпадает с планом выше; веса и архитектура закрыты, повторить можно только своим датасетом/моделью. Ссылка: https://detectwalls.com/
