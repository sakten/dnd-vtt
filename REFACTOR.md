Замеры на крипте (726 клеток, 102 стены, свет Wall of Light 120 фт): свет 9.7 мс до границ карты / 1.3 мс после (общий кэш + троттлинг — `client/src/lib/light.ts`), вьюпорт-вуаль ~1.0 мс на пересчёт. Честный LOS нужен ради точности/вида (клеточные артефакты на углах), а не ради текущего перфа.
**Вариант 1 — гибрид (визуал, дешёвый):** логика/туман остаются клеточными, вуаль рисуется одним честным полигоном видимости (лучи к концам стен ± ε, сортировка по углу, union по зрителям) — одна маска вместо сотен rect'ов. Стоимость O(W²) на зрителя (102 стены ≈ 21k пересечений ≈ 0.2–0.5 мс), при 500+ стенах растёт квадратично; вижн-зоны (мгла/магтьма/`opaque` Wall of Light) вычитать сегментами.
**Вариант 2 — полный (логика + визуал):** полигон + scanline-растеризация в клетки (O(W log W + клетки) вместо O(клетки × W)) заменяет `visibleCells`/`lightCells`; клеточный туман (`fog.hidden`), `canSee`/`enterableCell` и серверные проверки сохраняются, нужен единый геометрический контур (стены+зоны) и инвариантный тест «полигон = старый клеточный». Точнее и может быть быстрее на больших картах, но это заметный проект.
**Проверочный шаг:** спайк-бенч на данных крипты (лучи + маска/scanline) против текущих цифр; discriminating-тест на угловой артефакт (луч сквозь щель между стенами).

## R19. Метамагия (Careful Spell и др.): архитектура каст-модификаторов. P3, S/M (проектирование; решить перед реализацией).
Контекст: метамагия сорка меняет конкретный каст, не спеку: Careful (защищённые цели — автоуспех сейва + 0 вместо половины), Heightened (помеха на сейв цели), Twinned (вторая цель), Quickened (действие → бонусное), Subtle (компоненты/тишина), Empowered (переброс костей), Extended (длительность). «Природно безопасные» спеллы (Spirit Guardians) — другое правило: `side:'hostile'` исключает союзников из целей, а не форсирует им успех.
Варианты архитектуры:
- **A. Оверрайд эффективного дефа на касте:** `def = { ...baseDef, careful: true }`; `runSave` читает поле дефа, отсутствие = false (Fireball ничего не декларирует). Плюсы: дешевле некуда, один резолв на врождённое свойство и метамагию, аддитивно. Минусы: 8 опций → поля-свалка в `AutomationDef` и ветки в 5 подсистемах (сейвы/таргетинг/экономика/броски/длительность), валидация размазана.
- **B. Namespaced каст-параметр:** `spell:cast.metamagic = { careful?: … }`; подсистемы читают свои ключи (`runSave` — careful, `attackSources` — heightened, экономика — quickened). Плюсы: чистый контракт каста, стоимость/валидация в одном месте. Минусы: врождённое свойство спела и каст-параметр — два источника одного правила.
- **C. Пайплайн трансформов:** опция = данные + `apply(def, ctx)`/`validate`/`cost`; хендлер прогоняет `def = transforms.reduce(...)` (Careful → `{...def, careful:true}`, Heightened → `saveDisadvantageIds`, Twinned → `targets+1`, Quickened → `castCost:'bonus'`). Плюсы: композиция, порядок зафиксирован, unit-тесты на опцию, путь к CUSTOM-метамагии. Минусы: дороже сейчас; для Quickened/Twinned всё равно нужны потребители в экономике/таргетинге.
Рекомендация: для первой опции (Careful) — A; переход на C при ≥2 опциях или первой «не-деф» (Quickened/Twinned) — по тому же принципу ожидания, что R14 («ждём 2+ реактивных спелла»). B — промежуточный, если хочется заранее вычистить контракт каста.
Зафиксировано по обсуждению: **без UI выбора** — авто-союзники среди целей каста (`sideMatches(caster, t, 'ally')`); кап по CHA — решить при реализации (значение поля vs константа). Стоимость и лимиты (Sorcery Points, «спелл требует сейв») — в хендлере каста, не в спеках.
